# Studentory UI Specification

상태: `Draft — Keepers Note 방향 반영, 사용자 검토 필요`

이 문서는 Studentory의 UI 구현과 리뷰에서 사용하는 기준이다. 기능 요구사항은 `PRODUCT_SPEC.md`, 작업 완료 조건은 `docs/ROADMAP.md`를 우선한다. 이 문서가 승인되기 전에는 색상 체계나 레이아웃을 대규모로 변경하지 않는다.

## 1. 사용자와 사용 환경

주 사용자는 학생과 수업 정보를 반복해서 조회하고 기록하는 선생님이다.

- 데스크톱과 노트북 사용을 우선한다.
- 수업 전후의 짧은 시간에도 필요한 정보를 빠르게 찾을 수 있어야 한다.
- 학생 이름, 일정, 준비 상태, 출결과 다음 행동이 장식보다 우선한다.
- 긴 메모와 많은 학생 데이터에서도 화면이 무너지지 않아야 한다.
- 모바일은 핵심 업무가 불가능하지 않은 수준을 보장하되, 데스크톱과 같은 정보 밀도를 강제하지 않는다.

## 2. 기준 서비스

주요 UX 레퍼런스는 [Keepers Note](https://keepersnote.kr/)다. 실제 사용자가 이 서비스를 자주 사용하고 편하게 느끼므로, Studentory의 새로운 화면은 별도 학습이 필요하지 않도록 유사한 탐색 감각과 정보 구조를 우선한다.

2026-08-30 공개 웹과 앱 소개에서 확인한 참고 요소:

- 홈에서 자주 쓰는 정보와 기능을 한눈에 찾는 허브 구조
- 아이콘과 짧은 한글 라벨을 함께 사용하는 명확한 탐색
- 검색과 필터를 통한 빠른 항목 접근
- 정보 성격에 따른 그리드 보기와 목록 보기
- 오늘의 할 일, 타이머, 완료 표시처럼 즉시 조작 가능한 반복 업무
- 상세 화면에 들어가기 전에 카드나 목록에서 핵심 상태를 확인하는 방식
- 현재 시즌처럼 지금 필요한 항목을 우선하고 지난 항목을 필터로 분리하는 방식
- 지도, 도감, 요리처럼 복잡한 정보를 기능 단위로 분리하되 앱 전체에서는 일관되게 연결하는 방식

### 공개 페이지 직접 분석

2026-08-30 공개 페이지를 Desktop과 Mobile에서 직접 확인했다. Studentory에 적용할 패턴은 다음과 같다.

- 데스크톱 상단 탐색은 아이콘과 짧은 한글 라벨을 함께 사용하고 현재 위치를 둥근 선택 배경으로 구분한다.
- 모바일은 상단의 핵심 행동만 유지하고 전체 메뉴를 별도 서랍 탐색으로 전환한다.
- 상단에는 전역 행동, 본문에는 현재 시점에 필요한 정보와 반복 업무를 우선 배치한다.
- 큰 기능 영역 안에서 카드, 필터, 진행률과 빠른 행동을 묶어 관계를 이해하기 쉽게 만든다.
- 넓은 화면에서는 여러 정보 영역을 동시에 보여주고 좁은 화면에서는 한 열 흐름으로 재배치한다.
- 파스텔 계열 배경, 둥근 패널, 작은 아이콘, 낮은 그림자와 제한적인 포인트 오브젝트가 친근한 분위기를 만든다.
- 동일한 강도의 장식을 반복하지 않고 중요한 상태와 행동에 시선을 모은다.

공개 페이지의 캐릭터, 게임 이미지, 로고, 고유 문구, 브랜드 SVG와 저작권 자산은 사용하지 않는다. 구조와 분위기는 참고하되 Studentory의 교사 업무와 자체 시각 언어로 다시 설계한다.

공개 페이지에서 직접 확인하지 못한 로그인 내부 화면, 정확한 색상값, 글꼴, 간격은 추측하지 않는다. 사용자가 제공하거나 승인한 스크린샷이 생기면 해당 이미지를 시각 기준선으로 우선한다.

## 3. 시각 방향

### 목표

- 친근하지만 신뢰할 수 있는 생활형 업무 도구
- Keepers Note처럼 처음 보아도 기능을 쉽게 짐작할 수 있는 인상
- 답답한 관리자용 ERP보다 가볍고 정돈된 인상
- 높은 정보 밀도에서도 명확한 계층과 충분한 호흡
- 화려함보다 빠른 탐색과 실수 방지

### 현재 초안

- 밝고 부드러운 배경과 구분이 분명한 작업 영역을 사용한다.
- 기능을 빠르게 구별할 수 있도록 간결한 아이콘과 한글 라벨을 함께 사용한다.
- 강조색은 Keepers Note 레퍼런스를 실제 화면으로 확인한 뒤 확정하며, 한 화면에서 제한적으로 사용한다.
- 초록색은 완료·정상, 빨간색은 오류·파괴적 행동에 사용한다.
- 패널과 컨트롤은 친근한 인상을 주는 일관된 곡률을 사용한다.
- 경계, 배경 차이, 여백을 기본으로 하되 핵심 카드에는 낮은 그림자를 허용한다.
- 화면 제목과 탐색 명칭은 한글을 우선한다. 현재 영어 eyebrow는 제거 후보로 본다.
- 표가 효율적인 데이터는 표로 유지하되, 일일 업무와 상태 요약은 카드·목록·체크 표현을 우선 검토한다.

### 장식 적용 원칙

- 장식은 사용자 취향과 친근함을 만드는 기능적 요소로 인정하고 적정 수준으로 사용한다.
- 부드러운 배경색, 둥근 패널, 작은 도메인 아이콘, 가벼운 패턴과 포인트 오브젝트를 허용한다.
- Studentory 자체 아이콘과 CSS 기반 도형을 우선 사용하고 출처가 불명확한 외부 에셋을 추가하지 않는다.
- 장식은 학생 이름, 일정, 상태, 오류와 주요 행동보다 강하게 보이지 않아야 한다.
- 모바일에서는 장식 때문에 핵심 정보가 밀리거나 스크롤이 불필요하게 늘어나지 않게 한다.
- 사용자가 화면을 검토한 뒤 장식 밀도, 색상과 곡률을 조정한다.

### 피해야 할 방향

- 모든 정보를 카드로 분리해 화면이 조각나 보이는 구성
- 테두리, 배지, 강조색을 모든 요소에 반복하는 구성
- 작은 글자와 좁은 행간으로 정보량만 높이는 구성
- 업무 맥락과 연결되지 않는 장식, 과도한 그라데이션과 그림자
- 색상만으로 상태를 전달하는 방식
- 같은 화면에 동일한 강도의 주요 버튼이 여러 개 있는 구성
- Keepers Note의 게임 이미지, 캐릭터, 문구, 브랜드 자산을 모방하는 구성
- 친근함을 이유로 업무 정보의 정확성이나 가독성을 낮추는 구성

## 4. 디자인 원칙

### 익숙한 진입점을 제공해야 한다

- 첫 화면은 오늘 확인하거나 처리할 일을 보여주는 허브 역할을 한다.
- 주요 기능은 아이콘과 짧은 한글 라벨로 식별한다.
- 자주 쓰는 기능은 한 단계 안에 도달할 수 있게 한다.
- 사용 빈도가 낮은 관리 기능은 주 탐색과 분리한다.
- 메뉴 순서는 구현 편의가 아니라 실제 사용 빈도를 기준으로 정한다.

### 작업 우선순위가 보여야 한다

- 화면마다 가장 중요한 행동 하나를 명확히 한다.
- 파괴적 행동은 주요 행동과 떨어뜨리고 확인 단계를 둔다.
- 다음 행동이 없는 정보에는 버튼처럼 보이는 스타일을 사용하지 않는다.

### 훑어보기 쉬워야 한다

- 학생 이름, 날짜, 상태처럼 비교하는 값은 열과 기준선을 맞춘다.
- 라벨과 값의 대비를 일관되게 유지한다.
- 긴 텍스트는 핵심 목록의 높이를 무제한으로 늘리지 않는다.
- 빈 값은 `-`, 미입력, 없음 중 도메인 의미에 맞는 표현을 일관되게 사용한다.
- 카드나 목록에서는 핵심 상태만 보여주고, 긴 내용은 상세 화면에서 점진적으로 공개한다.
- 사용자가 비교 방식에 따라 그리드와 목록 보기가 모두 유용하면 전환을 제공하고 선택을 유지한다.

### 검색과 필터가 가까워야 한다

- 학생, 수업, 교재처럼 항목이 늘어나는 화면은 검색을 주요 진입점 가까이에 둔다.
- 필터명은 도메인 용어를 그대로 사용하고 현재 적용된 조건을 항상 보이게 한다.
- 현재 업무와 종료·지난 데이터를 기본 화면에서 섞지 않고 필터로 접근하게 한다.
- 검색 결과가 없을 때 전체 데이터가 없는 상태와 다른 안내를 제공한다.

### 상태가 명확해야 한다

- 로딩, 빈 상태, 검색 결과 없음, 오류를 서로 다른 문구와 형태로 표현한다.
- 저장 중에는 중복 제출을 막고 진행 상태를 텍스트로 알린다.
- 성공 후에는 목록과 상세 데이터가 즉시 최신 상태가 되어야 한다.
- 오류 메시지는 실패한 작업과 사용자가 할 수 있는 다음 행동을 설명한다.

### 일관성이 새로움보다 우선한다

- 기존 버튼, 입력, 모달, 패널을 우선 재사용한다.
- 같은 의미의 상태는 모든 화면에서 같은 색과 용어를 사용한다.
- 새로운 시각 패턴은 두 곳 이상에서 실제로 필요할 때만 공통화한다.

## 6. 탐색과 화면 구조

### 전역 탐색

- 데스크톱은 좌측 탐색, 좁은 화면은 하단 또는 압축된 탐색을 우선 검토한다.
- 아이콘만 사용하지 않고 한글 라벨을 함께 제공한다.
- 학생, 수업, 교재, 상담 중 현재 위치가 분명해야 한다.
- 오늘 자주 쓰는 학생과 수업은 관리 기능보다 먼저 노출한다.

### 홈 허브

Keepers Note의 한눈에 보는 홈 경험을 Studentory의 교사 업무에 맞게 적용한다.

1. 오늘 수업과 준비 상태
2. 곧 필요한 상담과 미완료 기록
3. 빠른 학생 검색
4. 자주 쓰는 추가·기록 행동
5. 최근 확인한 학생 또는 이어서 할 작업

홈은 모든 도메인의 축소판이 아니다. 오늘의 판단과 다음 행동에 필요한 정보만 제공한다.

## 7. 화면별 정보 우선순위

### 학생 목록

1. 학생 검색과 필터
2. 학생 이름과 현재 상태
3. 단계와 정기 수업 일정
4. 학생 추가
5. 상세 이동

목록의 한 행에서 모든 학생 정보를 보여주려 하지 않는다. 비교와 선택에 필요한 정보만 남기고 상세 기록은 학생 상세 화면에서 제공한다.

- 기본 목록 보기를 우선하되, 사진이나 시각적 상태가 실제로 중요해질 때만 그리드 보기를 추가한다.
- 활성 학생을 기본으로 보여주고 종료 학생은 명시적 필터로 접근한다.
- 검색어와 필터 상태는 상세 화면에서 돌아왔을 때 유지한다.

### 학생 상세

1. 학생 식별 정보와 상태
2. 정기 수업 일정
3. 특이사항과 요청사항
4. 수정
5. 삭제

삭제는 수정과 동일한 시각적 강도로 강조하지 않는다.

### 수업 현황

1. 조회 중인 주간과 이동
2. 오늘 또는 선택 날짜의 수업
3. 준비, 진행, 출결 상태
4. 수업 기록
5. 수동 수업 추가

한 주의 정보가 많아도 가로 스크롤에만 의존하지 않도록 데스크톱과 좁은 화면의 표현을 별도로 검토한다.

- 오늘 또는 이번 주에 필요한 수업을 기본으로 보여주고 지난 수업은 필터로 접근한다.
- 준비 완료, 출결, 기록 완료는 체크나 짧은 상태 라벨로 즉시 변경할 수 있게 검토한다.
- 사용자가 자주 반복하는 기록은 상세 모달을 열지 않고도 안전하게 처리할 수 있는 빠른 행동을 제공한다.

### 생성·수정 모달

1. 현재 작업의 제목
2. 필수 입력
3. 필드별 도움과 오류
4. 저장
5. 취소

모달이 열리면 첫 유효 입력 또는 제목으로 포커스를 이동한다. 닫히면 모달을 연 요소로 포커스를 돌려준다.

| Desktop | `1440 × 900` | 주 사용 환경과 정보 밀도 |

| Mobile | `390 × 844` | 레이아웃 파손과 핵심 조작 가능 여부 |

세 크기에서 가로 잘림, 겹침, 화면 밖 행동 버튼, 읽을 수 없는 축약이 없어야 한다.

## 9. 상태 검증 매트릭스

| 화면 | 필수 상태 |
| --- | --- |
| 학생 목록 | 로딩, 빈 목록, 데이터 있음, 검색 결과 없음, API 오류, 많은 데이터 |
| 학생 생성 | 기본, 입력 오류, 저장 중, 서버 오류, 성공 |

| 학생 수정 | 기본, 입력 오류, 저장 중, 서버 오류, 성공 |
| 수업 현황 | 로딩, 빈 주간, 수업 밀집, 날짜별, 학생별, API 오류 |

관련 기능이 아직 구현되지 않은 상태는 리뷰 결과에 `Not implemented`로 기록한다. 임시 UI를 만들어 검사를 통과시키지 않는다.

## 10. UI 평가 루브릭

각 항목을 해당 배점 내에서 평가하고 근거를 남긴다.

| 항목 | 배점 | 평가 기준 |
| --- | ---: | --- |
| 정보 계층 | 20 | 중요한 정보와 행동이 먼저 보이는가 |
| 친숙성과 탐색 | 15 | Keepers Note 사용자에게 진입점과 이동 방식이 쉽게 이해되는가 |
| 가독성과 밀도 | 15 | 빠르게 훑을 수 있고 과밀하지 않은가 |
| 작업 흐름 | 20 | 다음 행동, 진행 상태, 결과가 명확한가 |
| 일관성 | 10 | 패턴, 용어, 상태 표현이 일관적인가 |
| 반응형 안정성 | 10 | 검증 뷰포트에서 파손 없이 사용할 수 있는가 |
| 접근성 | 10 | 키보드, 포커스, 라벨, 대비가 적절한가 |

완료 기준:

- 총점 `90/100` 이상
- 항목별 점수가 배점의 70% 미만인 항목 없음
- 관련 기능 검증과 브라우저 콘솔 검사 통과
- 사용자 승인이 필요한 시각 변경은 승인 완료

점수는 결함을 숨기기 위한 평균값으로 사용하지 않는다. 키보드로 작업을 완료할 수 없거나 주요 정보가 잘리면 총점과 관계없이 실패다.

## 11. 검토 증거

UI 리뷰에는 다음을 남긴다.

- 검토한 화면과 상태
- 뷰포트 크기
- 기준 스크린샷 또는 변경 전후 이미지 경로
- 루브릭 점수와 감점 근거
- 브라우저 콘솔 오류 여부
- 자동화하지 못한 상태
- 사용자 확인이 필요한 시각 결정
- Keepers Note와 비교한 탐색·정보 구조의 공통점과 의도적인 차이

Goal 작업 중에는 요약을 `docs/LOOP_LOG.md`에 기록한다. 기준 스크린샷 디렉터리는 시각 테스트 도구가 승인된 뒤 정한다.
