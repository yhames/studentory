# DEC-LESSON-001: 수업 생명주기

상태: Approved

승인일: 2026-09-05

관련 Issue: [#10](https://github.com/yhames/studentory/issues/10)

## 결정

### 완료 조건

- 수업은 출석 또는 결석이 기록된 뒤 명시적인 완료 동작으로 `COMPLETED`가 된다.
- 진도와 수업 메모는 MVP 완료의 필수값이 아니다.
- 완료된 수업은 명시적인 복구 동작으로 `SCHEDULED` 상태로 되돌릴 수 있다.

### 정기 일정에서 수업 생성

- 수업현황에서 사용자가 조회한 날짜 범위에 필요한 수업을 on-demand로 생성한다.
- 주기적인 전체 선생성 작업은 MVP 범위에서 제외한다.
- 동일한 정기 일정과 날짜 조합은 멱등하게 한 번만 생성한다.

### 정기 일정 변경

- 일정 변경은 이후 아직 생성되지 않은 수업에만 적용한다.
- 이미 생성된 수업의 날짜, 시간, 상태와 기록은 변경하지 않는다.
- 기존 수업을 옮겨야 할 때는 원본을 취소하고 수동 수업을 새로 만든다.

### 취소와 보강

- 취소한 수업은 삭제하지 않고 `CANCELED` 상태로 보존한다.
- 취소는 `SCHEDULED`로 복구할 수 있다.
- 보강 수업은 별도의 수동 수업으로 생성한다.
- MVP에서는 취소 수업과 보강 수업 사이의 직접 연결 필드를 추가하지 않는다.

### 정기 일정 개수

- MVP에서는 학생별 활성 정기 일정을 하나만 허용한다.
- 복수 활성 일정은 실제 요구가 확인된 뒤 별도 제품 결정, migration, API와 UI 작업으로 확장한다.

## API와 데이터 영향

- 현재 `SCHEDULED`, `COMPLETED`, `CANCELED` 상태와 `complete`, `reopen`, `cancel`, `restore` 명령을 유지한다.
- 현재 조회 범위 기반 `POST /lessons/generate`와 `(schedule_id, lesson_date)` 고유 제약을 유지한다.
- 정기 수업의 날짜·시간 직접 수정 제한과 수동 수업 생성 방식을 유지한다.
- 기존 데이터 migration은 필요하지 않다.

## 후속 작업
